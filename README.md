# Crash Course: Agentic Engineering — Capstone

Фінальний проєкт курсу **fwdays · Crash Course: Agentic Engineering** (вересень 2026).

Слайди курсу: <https://koldovsky.github.io/2026-agentic-engineering-crash-course/>
Демо-репозиторії занять: [`…-day01`](https://github.com/koldovsky/2026-agentic-engineering-crash-course-day01) · [`…-day02`](https://github.com/koldovsky/2026-agentic-engineering-crash-course-day02)

## Що зробити

**Побудуй невеликий власний проєкт** — будь-який, який тобі цікавий.

Стек вільний: Next.js, Python, Go, Rust, мобільний застосунок, CLI, бот — на твій вибір.

**Масштаб скромний.** Краще маленький проєкт, проведений через повний інженерний цикл, ніж великий
«наче працює».

**Застосуй практики Agentic Engineering з курсу** — стільки, скільки доречно для твого проєкту:

- **контекст-інженерія** — правила / `AGENTS.md`, статичний vs динамічний контекст;
- **цикли (loop engineering)** — замість ручного покрокового промптингу;
- **верифікація** — тести / evals / перевірки замість «здається, працює»;
- **maker ≠ checker** — окремий агент або прохід на рев'ю;
- **специфікації наперед (SDD)** — якщо доречно.

**Project Factory** — за бажанням, не обов'язково (хочеш повну фабрику — запусти
`/project-factory:init` у себе).

**Запиши відео-демо на 1–2 хвилини:** коротко покажи продукт і розкажи, як саме ти будував(ла) його
агентно.

> Рівень глибини обираєш ти. Не оцінюється ні обсяг коду, ні кількість застосованих практик.
> Оцінюється те, що практики **справді є** і що кожна з них **коректно доведена** — на неї можна
> подивитися: файл, коміт, тест, прогін, запис.

## Як здати

**1. Зроби fork цього репозиторію** — разом із ним приїде шаблон PR.

```bash
gh repo fork koldovsky/2026-agentic-engineering-crash-course-capstone --clone
```

**2. Поклади свій проєкт у форк на окрему гілку** (будь-яким стеком).

```bash
cd 2026-agentic-engineering-crash-course-capstone
git checkout -b <твоє-ім'я>
```

Файли курсу в корені (`README.md`, `RUBRIC.md`, `.github/`) не чіпай — просто додай свій проєкт
поруч. Найзручніше покласти його в окрему теку, наприклад `submissions/<твоє-ім'я>/`: так у diff
видно рівно твою роботу.

Якщо зручніше тримати код в **окремому репозиторії** — тримай, і додай на нього посилання в описі PR.
У такому разі гілка у форку може містити лише короткий `README.md` із посиланням.

**3. Відкрий Pull Request і заповни шаблон:**

- **Ім'я** (справжнє — воно піде в сертифікат);
- **посилання на відео-демо** (1–2 хв);
- **опис застосованих практик Agentic Engineering** — що саме ти робив(ла) агентно, які інструменти /
  MCP використав(ла), що вирішував(ла) ти, а що агент.

PR може лишатися відкритим — зливати його не треба.

Що саме вважається доказом для кожної практики — **[RUBRIC.md](./RUBRIC.md)**.
Сертифікат — після прийнятого capstone. Дедлайн оголошується в чаті курсу (fwdays).
